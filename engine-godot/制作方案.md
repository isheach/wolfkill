# Godot 空想圣杯 · 制作方案

## 目标
用 Godot 4.7.2 (.NET/C#) 将现有 C 引擎(空想圣杯 KsG,758 条资源)
做成可操作图形程序:建卡 UI(搜索/滑条)→ 本地存档 → 对战结算(手动层数输入)。

## 环境
- Godot: `D:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64`(已确认 4.7.2.mono ✓)
- .NET SDK: 8.x(正在安装,Godot C# 项目编译必需)

## 转译策略(数据从 C 到 JSON)
编写 Python 脚本 `tools/export_resources.py`:
- 解析 `ksg_data.c` + `ksg_db.c` 中所有 `def_skill/def_np/def_item/db_skill/db_np/def_item_compat`
  及紧随的 `add_eff/db_eff(...)` 调用、`set_text/db_set_text` 文本
- 输出 `ksg_resources.json`:
```json
{ "resources": [
  { "id":1, "name":"对魔力", "kind":"skill", "type":"class",
    "rank":"B", "when":"passive", "cost":0, "recast":0, "feat":["main"],
    "effects":[ {"flag":"hit_pen","value":10,"target":"self",
                 "cond":{},"chance":0} ],
    "text":"令自身受到的…" }
] }
```
- 错误处理:解析失败条目记录到 log,不中断

## 引擎 C# 端口范围(与 C 版一一对应、手工核对)
| C 模块 | C# 对应 | 说明 |
|---|---|---|
| ks_check_* | Dice/CheckResult | 基础/最终成功率、负面判定抗性 |
| ks_mp_* | KsgWorld.Mana | 池/消耗/供给/结算/转移 |
| ks_recast_* | KsgWorld.Recast | 工序+1 回合+3 |
| ks_status_* | KsgStatus | 状态赋值/衰减/免疫/抵抗 |
| ks_effect_targets/check | KsgEffects | 目标解析(0/-1/-2)+条件+判定 |
| ks_battle_* | KsgBattle | 战斗位/工序机/战术环/指令/撤退FP/对决 |
| 结算链 | KsgEffects.ChainResolve | 宝具→技能→礼装 → 等级 → 时机 |

## UI 细节(需求逐条对应)
1. **搜索建卡**:TextBox 输入名称→实时过滤列表;点选技能加入卡面
2. **滑条建卡**:职阶/等级(40~70)/属性分配(每5点)/体力条→ 用 HSlider 直观分配
3. **本地保存**:`SaveManager` 存到 `user://saves/*.json`(列出/加载/覆盖/删除)
4. **对战**:两名已建卡单位→战术选择→工序提交→结算日志面板
   层数类技能(伤疤/疲惫/毒/灼伤等):战斗中触发时弹 SpinBox 手动输入层数,
   由 KsgStatus 应用层数与后续判定
5. 结算日志仿 C 版文本格式,便于对照

## 风险与对策
- .NET SDK 安装失败 → winget / 官方离线包;再不行用 Godot 的 GDScript 版(但需求指定 C#)
- 转译器解析复杂 C 宏 → 分层:先解析简单函数调用(占95%),结构化字面量块用手工处理
- Godot 4.7 尚无稳定中文文档 → 使用 4.x 标准 API(Control/HSlider/LineEdit 等)
- 时间柜:C# 编译需要 dotnet build;Godot 用 dotnet 模式导入
