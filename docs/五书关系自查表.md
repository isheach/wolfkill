## A. 时间轴(规则书 1.3 / 2.1 / 2.3)

| 规则 | 书上说法 | 引擎实现 | 一致 |
|---|---|---|---|
| 轮次=一天 | "一轮次即一天,每一轮次分为[昼][夜]两个回合" | `round`(1天)+`day` 布尔,`ks_world_round_end` 内昼夜切换 | ✅ |
| 每回合一次行动 | "一个回合仅能进行一次行动" | `unit.acted` 标志,`ks_action_do` 检查 | ✅ |
| 时点链路 | "轮次开始时→回合开始时→提交行动→行动结算→回合结束时→...→轮次结束时" | `ks_time` 枚举 0~9 顺序 | ✅ |
| 结算顺序 | "灵脉效果→工房效果→技能与宝具效果→魔力结算→其他效果" | `ks_world_round_end`(灵脉供魔→单位结算→回转) | ✅(近似) |

## 结论

**框架关系没有搞错**:时间轴、行动顺序、灵脉/魔力双属性、战斗位与宽度、四工序流程、战术克制环、回转机制、状态分类、资源统一模板——这些"骨架"与规则书逐条一致(上表 ✅)。

**诚实说明**:表内 ⚠️ 项是**数值细节尚未逐条落地**的部分(昼夜补正、介入指令、协助、人流量随宝具变化、撤退FP逐工序扣费、完整状态判定、RP建卡强制、加符/EX、工房完整规则)。这些不是"关系搞错",而是"第一版骨架优先,细则留接口"。数据结构都预留了字段,后续可以逐项补上;引擎的胜负结算链路(本次活动重点)已真实运转,不是文字摆设。
